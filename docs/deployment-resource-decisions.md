# Решения по размещению и ресурсам

Статус: **ожидает решения владельца продукта/эксплуатации**. Этот документ намеренно не подставляет предположения вместо значений, необходимых для выпуска.

## Уже зафиксировано дизайном

| Параметр | Принятое ограничение |
| --- | --- |
| Серверная модель | Один Node.js-процесс: in-memory registry не поддерживает горизонтальное масштабирование |
| Участники комнаты | Не более 4 |
| Хранение | Только RAM; после пустой комнаты или restart история удаляется |
| NAT | STUN без TURN; отдельная недостижимая P2P-пара допустима |
| Переполнение памяти | Нельзя молча удалять принятую историю |

## Требуемые решения

| Вопрос | Владелец | Нужное решение | Статус |
| --- | --- | --- | --- |
| Домен и HTTPS-среда | Владелец проекта | Домен, способ TLS, reverse proxy и один публичный origin | Не определено |
| Память процесса | Эксплуатация | Лимит RAM и допустимый RSS для одного процесса | Не определено |
| Целевая нагрузка | Владелец продукта | Одновременные комнаты/участники и ожидаемая продолжительность звонка | Не определено |
| Время жизни активного чата | Владелец продукта | Максимальная ожидаемая длительность живой комнаты | Не определено |
| Политика при бюджете RAM | Владелец продукта | Подтвердить `SERVER_BUSY` для новых сообщений без удаления принятой истории | Не определено |
| Очередь медленного клиента | Эксплуатация | Порог transport queue и правило отключения клиента | Не определено |

## Предлагаемая позиция для утверждения

При достижении согласованного бюджета RAM сервер прекращает принимать **новые** сообщения и отвечает `SERVER_BUSY`; уже принятые записи не удаляются и не сокращаются. Клиент сохраняет неотправленный текст только в памяти текущей вкладки и предлагает ручную повторную отправку. Масштабирование вторым независимым процессом не допускается, пока не появится отдельный дизайн владения комнатами.
