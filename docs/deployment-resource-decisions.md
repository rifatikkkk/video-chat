# Решения по размещению и ресурсам

Статус: **принято для локальной фазы разработки**. Домен и production HTTPS будут выбраны перед выпуском.

## Уже зафиксировано дизайном

| Параметр | Принятое ограничение |
| --- | --- |
| Серверная модель | Один Node.js-процесс: in-memory registry не поддерживает горизонтальное масштабирование |
| Участники комнаты | Не более 4 |
| Хранение | Только RAM; после пустой комнаты или restart история удаляется |
| NAT | STUN без TURN; отдельная недостижимая P2P-пара допустима |
| Переполнение памяти | Нельзя молча удалять принятую историю |

## Требуемые решения

| Вопрос | Владелец | Нужное решение | Статус |
| --- | --- | --- | --- |
| Домен и HTTPS-среда | Владелец проекта | До выпуска — только localhost; домен, TLS и reverse proxy выбрать перед release | Принято с отложенным production-решением |
| Память процесса | Эксплуатация | Лимит RAM одного Node.js-процесса — 1 GB | Принято |
| Целевая нагрузка | Владелец продукта | До 10 одновременных комнат / 40 участников | Принято |
| Время жизни активного чата | Владелец продукта | До 4 часов на активную комнату | Принято |
| Политика при бюджете RAM | Владелец продукта | `SERVER_BUSY` для новых сообщений без удаления принятой истории | Принято |
| Очередь медленного клиента | Эксплуатация | Не реализовывать в этой версии; оформить как backlog | Принято |

## Предлагаемая позиция для утверждения

При достижении согласованного бюджета RAM сервер прекращает принимать **новые** сообщения и отвечает `SERVER_BUSY`; уже принятые записи не удаляются и не сокращаются. Клиент сохраняет неотправленный текст только в памяти текущей вкладки и предлагает ручную повторную отправку. Цель для нагрузочных проверок — 10 комнат, максимум 40 участников и до 4 часов жизни активной комнаты при лимите Node.js-процесса 1 GB. Масштабирование вторым независимым процессом не допускается, пока не появится отдельный дизайн владения комнатами.
