# Журнал репетиции выпуска и отката (задача 72)

Дата: 2026-09-26  
Стенд: локальный Windows, один Node.js-процесс, без nginx и внешнего TURN.

## Выпущенная пара

Для репетиции использована совместимая пара из одного коммита `main`:

- client: Vite production build из текущего коммита;
- server: Node.js server из того же коммита;
- протокол: `PROTOCOL_VERSION = 1`.

Перед запуском выполнены `npm ci`, `npm run check:versions` и `npm run build`. Второй Node.js-процесс намеренно не запускался.

## Журнал действий и результата

| Шаг | Действие | Ожидание | Результат |
| --- | --- | --- | --- |
| 1 | Запуск совместимой client/server-пары | Процесс слушает один порт | Пройдено; `/healthz` возвращает `200`, `/readyz` — `200` и `{"status":"ready"}` |
| 2 | Подключение двух клиентов и создание комнаты | Участники видят комнату и могут обменяться сообщениями | Пройдено smoke-сценариями browser/chat |
| 3 | Проверка остановки | Readiness закрывается до завершения процесса | Пройдено; `/readyz` возвращает `503`, клиенты получают `server:closing`, новые входы получают `SERVER_BUSY` |
| 4 | Контроль единственного экземпляра | Нет перекрытия старого и нового Node.js-процесса | Пройдено процедурой: новый процесс запускается только после освобождения порта старым |
| 5 | Проверка несовместимого клиента | Клиент получает `PROTOCOL_MISMATCH` | Пройдено integration-тестом с другой версией envelope |
| 6 | Откат | Остановить новую пару и вернуть предыдущую совместимую пару | Пройдено процедурой из runbook: остановка, проверка освобождения порта, запуск предыдущего client/server-коммита и повтор health/readiness/chat-проверок |

## Автоматические подтверждения

- `npm test`: unit и integration тесты проходят, включая readiness/shutdown и `PROTOCOL_MISMATCH`.
- `npm run test:smoke -- --workers=1`: 13/13 сценариев проходят, включая соединение двух браузерных контекстов, чат и четыре участника.
- `npm run build`: production-клиент собирается.

## Ограничения репетиции

Это локальная репетиция без реального TLS-сертификата, NAT и TURN. HTTPS-поведение относится к nginx-конфигурации и должно быть повторено на staging-домене. Откат не восстанавливает комнаты и in-memory историю: после остановки пользователи входят в новую комнату вручную.
